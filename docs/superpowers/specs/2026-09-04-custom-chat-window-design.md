# 江小满自定义聊天窗口设计

日期：2026-09-04

## 目标

用网站自有的聊天界面替换 Dify 原生 iframe。保留现有江小满首页和 GitHub Pages 公网入口，让用户看到统一的“满糖”视觉，并继续与已发布的江小满 Dify 应用进行真实多轮对话。

## 已确认的视觉

- 江小满消息位于左侧，头像使用现有人设主图的圆形缩略图。
- 用户消息位于右侧，头像使用已确认的匿名男性短发背影图。
- 聊天区域沿用奶油白、低饱和玫瑰、雾蓝和暖棕；不再显示 Dify 的黑色界面。
- 去掉平台菜单、机器人图标、耗时、Token、点赞、踩和复制等平台控件。
- 保留江小满在线状态、重新开始、消息输入框、发送按钮、回复生成状态和必要的 AI 身份说明。
- 桌面端保持现有 46/54 双栏；移动端采用上下堆叠，消息区无横向溢出。

## 技术边界与架构

公开的 GitHub Pages 只能托管静态前端，不能安全保存 Dify API Key。Dify 官方要求应用 API Key 只在后端使用，因此采用两层结构：

1. GitHub Pages 前端：React 自定义聊天界面，仅向受控代理发送消息，不持有 Dify Key。
2. Vercel 轻量代理：保存 `DIFY_API_KEY`，转发到 `https://api.dify.ai/v1/chat-messages`，限制允许来源并隐藏上游凭据。

开发阶段不需要真实 Key。前端和代理通过 mock fetch、固定 SSE 片段和契约测试完成。真实 Key 只在部署联调阶段由用户在 Vercel 的秘密输入位置亲自填写，不进入聊天、源码、日志、Git 历史或前端构建产物。

## 组件边界

### `ChatWindow`

负责聊天窗口布局、消息列表、空状态、错误提示和重新开始。它不直接知道 Dify Key，也不直接请求 Dify。

### `MessageBubble`

仅负责渲染单条用户或江小满消息、对应头像与流式输出状态。消息正文按纯文本安全渲染，不执行模型返回的 HTML。

### `ChatComposer`

负责输入、发送、回车行为、生成期间禁用和空消息拦截。发送失败后保留用户输入，便于重试。

### `useChatSession`

管理消息、`conversation_id`、稳定的匿名 `user` 标识、流式回复、取消请求和重新开始。会话标识只保存在当前浏览器本地。

### `chatClient`

封装对代理端点的请求与 SSE 解析。只接收前端所需字段；忽略上游的 Token、价格和内部工作流信息。

### `api/chat`

Vercel 服务端函数。校验请求体和来源，读取服务端 `DIFY_API_KEY`，调用 Dify Chat Messages API，并将允许的流式事件转发给前端。错误响应不包含密钥或上游敏感细节。

## 数据流

1. 用户输入消息，前端先显示右侧消息气泡。
2. 前端向代理发送 `query`、稳定匿名 `user` 和可选 `conversation_id`。
3. 代理用服务端 Key 调用 Dify 的 `POST /chat-messages` 流式接口。
4. 前端逐段拼接 `message` 或 `agent_message` 内容，并在结束事件中保存新的 `conversation_id`。
5. 用户点击“重新开始”时，仅清空本机消息与会话标识；不删除 Dify 后台数据。

## 错误与降级

- 未配置代理地址：显示“对话服务尚未连接”，不回退到暴露 Key 的浏览器请求。
- 网络断开：保留已有消息，恢复后允许重试。
- 401/403：显示“对话服务配置异常”，服务端日志只记录状态码，不记录 Key。
- 429：显示“现在来找江小满的人有点多，请稍后再试”。
- 5xx/流中断：保留已生成内容并提供重新发送。
- 原 Dify 页面保留为“直接打开原对话”的辅助链接，但不作为主界面。

## 安全与隐私

- `DIFY_API_KEY` 只存在于 Vercel 环境变量。
- `.env*` 继续被 Git 忽略，仓库只提供无真实值的 `.env.example`。
- 代理的 CORS 默认只允许正式 GitHub Pages 域名和本地开发源。
- 请求设置长度上限，拒绝异常方法、无效 JSON 和超长输入。
- 不在浏览器持久化 API Key、Token 用量、价格或上游原始日志。

## 测试与验收

- 单元测试：角色头像、消息方向、输入规则、重试和重新开始。
- 客户端测试：SSE 分片、结束事件、错误事件与 `conversation_id` 延续。
- 代理测试：来源限制、请求校验、Key 缺失、Dify 错误映射、Key 不泄漏。
- 浏览器测试：桌面与移动端布局、键盘发送、生成状态、无横向滚动。
- 成品扫描：`dist`、源码和 Git 历史中没有真实 Key 或 Bearer Token。
- 联调验收：公网发送一条无隐私消息，收到江小满回复，刷新后页面仍可正常开始新会话。

## 分阶段交付

1. 无密钥阶段：Pi Coding Agent 完成界面、代理、测试和本地 mock 验收；不推送破坏现有线上对话的版本。
2. 密钥阶段：用户在安全输入位置设置 Vercel Secret；完成真实 Dify 联调。
3. 发布阶段：配置前端代理地址，推送 GitHub，等待自动部署并进行公网验收。

## 不在本次范围

- 登录、账号体系、多设备同步、上传文件、语音、付费、聊天记录云端管理。
- 修改江小满 Dify 工作流、模型、提示词或知识库。
- 在前端或 GitHub 仓库保存 Dify API Key。
