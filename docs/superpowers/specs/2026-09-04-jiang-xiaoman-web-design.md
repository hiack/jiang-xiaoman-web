# 江小满对话网站设计规格

## 1 项目目标

建立一个可通过公网网址访问的单页网站，让访问者在江小满的角色氛围中直接使用现有 Dify 对话应用。网站必须保持江小满已确认的人设与主形象，桌面和手机均可使用，并由私有 GitHub 仓库保存源代码。

完成结果包括本地项目、私有 GitHub 仓库、自动构建配置和可联网访问的公开网站。网站公开不代表源代码公开。

## 2 已确认决策

- 角色视觉采用自然真人摄影感。
- 首页采用 A 方案沉浸式双栏。
- 桌面端左侧为角色主视觉，右侧为即时对话。
- 手机端压缩人物区，把对话区放在主要可视范围。
- 第一版通过 iframe 嵌入已发布的 Dify 对话，不使用 Dify API Key。
- GitHub 仓库设为私有。
- 上线网站允许公网访问。
- 优先使用 GitHub Pages。若账号套餐不支持私有仓库发布，保持仓库私有并停止发布，不擅自建立公开仓库或改用其他平台。
- Pi Coding Agent 负责实现；Codex 负责设计、代码与视觉验收、GitHub 和发布操作。

## 3 人设和内容边界

### 3.1 人物基准

江小满是 22 岁的成年中国女性，独立甜品店满糖的店主，兼职插画师。她有深栗色及腰微卷长发、浅棕杏眼，常穿奶白与浅粉的柔软衣物，气质温柔、羞怯、有分寸。

人物世界位于现代海边雾城。满糖甜品店在老街拐角，主要场景为傍晚五点半、小雨和薄雾。角色语言、剧情和回复逻辑由现有 Dify 应用负责，网站不得另写一套伪对话逻辑替代它。

### 3.2 视觉资产

- 选定文件：`F:\ai产品竞品分析\111\outputs\江小满网站素材\江小满_主形象_C版.png`
- 尺寸：1024 × 1536
- SHA-256：`7176C73A11EA631F624B8F9549EE1F5BFA2FFF5A161B2C0054508B76BD607870`
- 使用方式：桌面端环境主图、手机端裁切主图和圆形头像均从同一文件派生。
- 不允许重新生成、换脸、改变发色或改成动漫风格。
- 为性能优化而生成的 WebP 或 AVIF 版本必须保留同一构图和人物身份，原始 PNG 必须留在仓库资产目录。

### 3.3 固定界面文案

- 品牌名：`满糖 · 江小满`
- 场景提示：`雾城 · 傍晚五点半 · 小雨`
- 主句：`“……你来了呀。”`
- 副句：`靠窗的位置，我一直替你留着。如果今天有点累，就慢慢说。`
- 输入引导：`和江小满说句话…`
- 透明说明：`由你已发布的 Dify 对话提供回复`

界面可以显示一段静态开场提示，但实际对话内容必须来自 Dify，不得在网站层伪造模型回复。

## 4 页面和视觉系统

### 4.1 页面结构

网站只有一个主要页面，不增加注册、登录、付费、社区、角色商城或后台管理。

桌面端采用 46 比 54 的左右布局：

1. 左侧角色区展示主图、品牌名、场景提示、主句和副句。
2. 右侧对话区展示江小满头像、Dify iframe、加载状态和辅助入口。
3. 页脚或轻量抽屉提供 AI 身份、安全与隐私说明，不干扰主要聊天流程。

手机端采用上下布局：

1. 角色图片高度控制在约 140 到 180 像素。
2. 对话区占据剩余视口并保持可输入。
3. 不要求用户先滚过完整人物介绍才能聊天。

### 4.2 颜色和质感

- 主文字：`#362522`
- 奶油背景：`#FBF6F1`
- 低饱和玫瑰粉：`#CF777A`
- 雾蓝灰：`#D9E3E3`
- 暖灰辅助文字：`#79655F`
- 分隔线：`#EADFD9`

页面使用暖灯与窗外冷色雨雾形成温度对比。避免高饱和粉色、霓虹紫、科技蓝、玻璃拟态堆叠和通用 AI 星光效果。

### 4.3 排版与动效

- 中文界面使用可读性稳定的系统无衬线字体。
- 主句可使用系统衬线字体形成轻微文学感。
- 动效只用于页面淡入、加载指示和按钮反馈，并遵守 `prefers-reduced-motion`。
- 不使用自动播放声音、漂浮爱心、持续粒子动画或夸张打字机效果。

## 5 技术架构

### 5.1 项目技术

- Vite
- React
- TypeScript
- 普通 CSS 或 CSS Modules
- Vitest 和 React Testing Library 用于组件测试
- Playwright 或等价浏览器检查用于关键页面冒烟测试

不引入数据库、账号系统、分析 SDK、广告脚本或自建服务端。

### 5.2 组件边界

- `AppShell`：页面外框、响应式布局和全局错误边界。
- `CharacterHero`：主图、品牌和场景文案，只负责角色展示。
- `ChatPanel`：Dify iframe、加载状态、超时状态和重试操作。
- `SafetyInfo`：AI 身份、隐私边界和高风险提示。
- `ExternalChatLink`：在嵌入失败时打开原始 Dify 对话。

每个组件只承担一种职责。Dify 地址集中在一个配置文件中，不能散落在组件或测试代码里。

### 5.3 数据流

1. 浏览器从公开网站加载静态 HTML、CSS、JavaScript 和角色图片。
2. `ChatPanel` 加载 `https://udify.app/chat/pNigFJHwFSH5pgcY`。
3. 访问者在 iframe 内直接与 Dify 通信。
4. 网站本身不读取、转发或存储聊天内容。
5. GitHub 仓库和构建产物中不出现 Dify API Key、访问令牌或用户凭据。

跨域限制意味着外层网站不能读取 iframe 内的消息内容，因此第一版不实现自定义消息气泡、聊天记录同步或跨页面会话控制。

## 6 加载和异常处理

- 首次加载显示与页面风格一致的轻量骨架或等待提示。
- iframe `load` 事件后隐藏等待提示。
- 超过合理时间仍未完成时显示说明、重新加载按钮和原始 Dify 链接。
- 浏览器阻止嵌入或 Dify 临时不可用时，不显示空白区域。
- 重新加载只刷新 iframe，不刷新整个网站。
- 外部入口在新标签页打开，并使用安全的链接属性。
- 没有网络时给出明确提示，不伪装成江小满回复。

## 7 安全 隐私与可访问性

- 明确标注江小满是 AI 角色，不宣称真人在线。
- 简洁说明聊天内容由 Dify 服务处理，本网站不直接保存聊天记录。
- 提醒访问者不要输入密码、身份证号、银行卡信息等敏感内容。
- 对自伤、医疗急症和现实危险不在网站层编写自动回复，实际处置由 Dify 工作流承担；网站安全说明提供联系当地紧急服务的通用提示。
- iframe 必须设置可理解的 `title`。
- 图片必须有与内容相符的替代文本。
- 键盘可访问加载失败后的重试和外部入口。
- 颜色对比、焦点样式和缩放后的布局必须可用。

## 8 GitHub 和发布

### 8.1 仓库

- 目标账号：`hiack`
- 仓库名：`jiang-xiaoman-web`
- 可见性：private
- 默认分支：`main`
- 不提交构建缓存、依赖目录、本地环境文件或视觉稿临时目录。

### 8.2 GitHub Pages

使用 GitHub Actions 构建 Vite 项目并发布静态产物。Vite `base` 必须匹配项目仓库路径。

发布前通过 GitHub API 尝试启用 Pages。若 GitHub 拒绝私有仓库发布：

1. 保持仓库私有。
2. 保留已经完成并通过验收的本地项目和远程仓库。
3. 记录 GitHub 返回的具体限制。
4. 停止在发布步骤并请求用户选择其他托管平台或升级套餐。

不得把仓库改为公开，也不得自动注册或绑定其他托管服务。

## 9 执行分工

### 9.1 Pi Coding Agent

Pi 从 `F:\picoding\node_modules\.bin\pi.cmd` 启动，在目标项目目录内执行以下工作：

- 建立前端项目和组件。
- 复制并优化已确认的角色图片。
- 实现响应式页面、加载与错误状态。
- 编写测试和构建配置。
- 输出实现报告、测试结果和仍未解决的问题。

Pi 不创建 GitHub 仓库、不推送、不启用 Pages、不更改已确认的人物图。

### 9.2 Codex

Codex 负责：

- 向 Pi 提供本规格和精确执行范围。
- 检查 Pi 的退出状态、文件变更和实现报告。
- 独立运行测试和生产构建。
- 独立检查桌面端和手机端视觉表现。
- 检查仓库中不存在密钥和不必要的个人信息。
- 创建私有 GitHub 仓库、推送代码并执行发布。
- 对最终公网网址进行 HTTP、视觉和真实聊天验收。

## 10 验收标准

只有以下条件全部满足，项目才能标记为完成：

1. 本地项目可从干净依赖安装后构建成功。
2. 自动化测试通过。
3. 生产构建中只有预期静态文件，不含 API Key、令牌或本地绝对路径。
4. 选定主图人物身份未改变，1024 × 1536 原始 PNG 被保留。
5. 1440 × 900 桌面视口无横向溢出、遮挡或裁切错误。
6. 390 × 844 手机视口可直接看到聊天区并完成输入。
7. Dify 正常时 iframe 可加载。
8. Dify 异常或超时时显示重试和原始对话入口。
9. 实际发送一条无敏感内容的测试消息并收到江小满回复。
10. GitHub 仓库为 private，远程地址属于 `hiack/jiang-xiaoman-web`。
11. GitHub 和构建日志未暴露凭据。
12. 公网地址通过 HTTPS 返回成功，并在桌面与手机宽度下完成最终视觉检查。

## 11 不在第一版范围内

- Dify API Key 和自定义后端代理
- 完全自定义聊天气泡或聊天记录数据库
- 用户登录、账号同步或支付
- 语音通话、视频、虚拟形象动画
- 多角色选择
- 管理后台、数据分析和埋点
- 自定义域名

这些功能只能在第一版稳定上线后另行设计和批准。

## 12 已知发布条件

GitHub 官方规则要求个人私有仓库使用 GitHub Pages 时具备支持该功能的付费套餐。当前 GitHub 接口未返回账号套餐，因此能否直接从私有仓库发布只能在仓库创建并尝试启用 Pages 时最终确认。此不确定性不影响本地实现和私有仓库交付，但可能阻塞最终公网地址。
